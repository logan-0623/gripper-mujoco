# Q2 第二步：从演示中途重启，10k 与 25k 的差距在哪一段

运行日期：2026-10-05 至 10-06，代码提交 `73d6cc3`，服务器为 RTX 4080 SUPER。实验脚本是 [demo_restart_rollouts.py](../../../scripts/demo_restart_rollouts.py)。

## 要回答的问题

10k 与 25k 的单步离线误差差别很小，闭环成功率却相差 27 个百分点（[Q2 第一步](../libero_smolvla_q0b_q6a_q1_20261005/README.md)）。差距从哪里来？事先写下的两种预期是：

- **误差在闭环中累积：** 起点越晚、剩余步数越少，两者的差距应该越小。
- **单步就差：** 即使从很晚的起点出发，差距也不会缩小。

## 方法

- **重启点：** 对 Spatial 0–3 每个任务，取原始 LIBERO 演示的前 10 条。在每条演示长度的 0%、20%、40%、60% 处取仿真状态，共 160 个重启点。10k 和 25k 使用完全相同的重启点。
- **恢复方式：** 先执行原生的环境 reset，再用 `set_init_state` 恢复演示状态，之后不再执行等待步（LeRobot 默认的等待动作会张开夹爪）。
- **评测设置：** 恢复之后，评测命令、随机种子、动作分块（执行 10 步）、10 步去噪、280 步上限都与能力时间轴一致。
- **排除规则：** 恢复后立即检查任务是否已完成，已完成的重启点不计入统计。本次没有任何重启点被排除。
- **冒烟测试暴露的问题：** 最初的 75% 起点在部分演示里已经满足任务目标，策略走 1 步就判为成功，所以改成了以上设置。

## 读法

1. **两种事先的预期都不完全成立。**
   - 差距并没有从起点开始随剩余步数平滑缩小：20% 起点的差距（+0.28）不小于 0% 起点（+0.20），而此时机械臂还没有抓到碗。
   - 40% 起点之后差距变小，CI 包含 0。
2. **差距集中在"接近 → 抓取"这一段。** 这与三条独立证据一致：
   - Q2 第一步：10k 在接触阶段与演示的夹爪一致率更低。
   - Q1：两个混合模型都主要卡在稳定抓取。
   - 强制掉落：10k 在 Spatial 1 上掉落后无法重新抓起，25k 可以。
3. **抓取之后，两者的差距明显缩小。**
4. **60% 起点不能用来下结论。** 25k 从这里出发也只有 30% 成功率，明显低于它在其他起点的表现。这更像是中途恢复仿真状态时，抓握接触或控制器内部状态没有被完整恢复，而不是策略本身的差别。

## 局限

- 每个起点 40 个重启点、一个训练 seed，按演示聚类的 CI 较宽。
- 0% 起点用的是演示的初始状态，不是基准测试的 50 个初始状态。10k 在这里是 65%，与它在基准初始状态上的 59% 接近。
- 起点按演示长度的比例来选，没有按"接近、抓取、搬运"等阶段对齐。下一步应该用接触和稳定抓取的时间点来定义起点，并且检查恢复后抓握是否保持住。
- 每条闭环的逐步事件留在服务器上（`/root/autodl-tmp/smolvla-official-reproduction-v2/acquisition/q2_restart_20261005/`）。本目录只保留汇总、重启点和恢复检查。
