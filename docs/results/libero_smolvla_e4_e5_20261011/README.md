## 设计

- **E4：四组都从 10k 出发，训练 5000 步，batch size 32，使用新的优化器。**
  - C：全量微调，不加权；
  - W：全量微调，窗口帧权重 ×3；
  - LE：LoRA 只加在 expert，窗口 ×3；
  - LA：LoRA 加在 expert 和 VLM 文本层，窗口 ×3。
  - 窗口为第一次合夹爪命令前 20 帧到后 25 帧，占全部训练帧的 27.2%（74,382 / 273,465）。
  - 每组评测 2500 步和 5000 步两个 checkpoint。
- **E5：** 原谱系的 15k、20k，与 E3 的 10k、25k 组成时间轴。
- **评测协议与 E3 相同：** 初态 0–19；不推时评 task 0–3（80 个回合）；推 8 步时评 task 0–1（40 个回合，实际推开约 5 cm）。
  - **保持率：** 不推时成功的初态中，推 8 步后仍然成功的比例（E3b 的主指标）。
  - **配对差：** 按（任务, 初态）配对，bootstrap 95% CI。
- **执行说明：**
  - 第一次评测中，8 个进程同时运行且没有限制 CPU 线程，每步约 7 秒，在 task 1 中途被关机截断。5000 步 checkpoint 的 task 0 结果沿用那次运行（协议相同），其余在补评中完成。补评限制每个进程 8 个线程。
  - 补评中 15k、20k 的输出目录名为 `k01_`、`k02_`（脚本取了 `015000`、`020000` 的前两位），汇总脚本已对应。

## 结论

1. **E5：吸引域沿时间轴跟随能力变化，主要变化在 10k→15k。**
   - 不推成功 50 → 66 → 67 → 69；推 8 步后的保持率 0.19 → 0.32 → 0.37 → 0.39。
   - 10k→15k 两项都有显著差别；15k 之后两项都进入平台，CI 都包含 0。吸引域与成功率的变化时间一致，没有看到"成功率饱和后吸引域仍继续变宽"。
2. **E4，5000 步：** 四组都回到原谱系 15k 的水平，相对 15k 和相对 C 的差都包含 0。窗口加权、只训 expert、加训 VLM 文本层，在这个预算下都没有可测的差别。
3. **E4，2500 步：** 只有窗口加权的组出现了提前的迹象。
   - W 推 8 步后的成功比 C 多 +0.15 [0.00, +0.30]，保持率 0.40 对 0.16。
   - LA 不推成功 +0.10 [−0.01, +0.21]。
   - 这两项的 CI 下界都贴着 0。
4. **预注册的加速判据没有满足。** 判据是"W 在 2500 步达到 C 在 5000 步的水平"：W@2500 不推 59/80，C@5000 是 66/80；推 8 步 13/40 对 17/40。
5. **LE 对 LA（Q1）：** 两个 checkpoint 上 LE 都略低于 LA，但差别都在 CI 内，不能区分"只训 expert 就够"和"需要 VLM 侧一起训"。

## 不能推出

- **2500 步的提前迹象只在一个指标上、CI 下界为 0。** 推 8 步只有 task 0–1，共 40 个回合；还没有更早的 checkpoint（例如 1000 步）来看曲线形状。
- 只有一个训练 seed，四组共用 seed=1000。
- C 在 5000 步就追平 15k，说明从 10k 继续训练本身很快；E4 能检验的加速空间只有大约 2500 步。
