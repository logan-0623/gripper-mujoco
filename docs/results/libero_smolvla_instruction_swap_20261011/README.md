# 换指令评测：能力形成有多少只是"布局 → 轨迹"？

运行日期：2026-10-11，服务器为 RTX 4080 SUPER。
- 脚本：[instruction_swap_eval.py](../../../scripts/instruction_swap_eval.py)。
- 结果：[summary.json](summary.json)；实际传给策略的指令见 [contract.json](contract.json)。
- 原始数据在服务器 `/root/autodl-tmp/instruction_swap_20261011/`。

## 要回答的问题

审稿人一定会问：F1 测到的"能力形成"（5k 12.5% → 25k 86%），是不是只是学会了"看到某个布局 → 执行对应轨迹"，而没有用到语言？

## 方法

- **不训练。** 只改评测时传给策略的 `task_description`：在 `LiberoEnv` 构造后覆盖该属性，lerobot_eval 会把它放进 `observation["task"]`，事件记录器同时把它记为 `language`。
- **四种条件：**
  - `correct`：任务自己的指令（在同一套评测里重跑，作为对照）；
  - `empty`：空字符串；
  - `gibberish`：与原指令词长相同的随机小写字母，每个任务固定一条；
  - `other`：另一个 Spatial 任务的指令（task k 用 task (k+1) mod 4 的指令）。Spatial 的指令只在"哪只黑碗"的指代上不同，目标都是"放到盘子上"。
- **其余设置与 E1/E2 相同：**
  - 5k–25k 五个 checkpoint，Spatial 0–3，每个任务初态 0–39，共 3200 个回合；
  - 固定逐回合噪声种子（`--policy-noise-seed-base 2057736129`），所以各条件可以按（任务, 初态）严格配对。
- **执行：** 12 个进程并行，每个进程限 8 个 CPU 线程（`OMP_NUM_THREADS=8`），全程约 4.5 小时。80 个任务全部完成，没有失败。
- **口径：** 接触、抓取、抬起都指原任务的目标碗（`akita_black_bowl_1`），事件记录器只追踪这只碗。

- **配对：** `correct` 下成功的回合共 507 个（5k–25k 合计）。换成 `empty` 后保住 0 个，`gibberish` 保住 1 个，`other` 保住 1 个。

## 结论

1. **去掉或替换指令后，成功都降到 0–1/160。** F1 的能力形成不能只用"布局 → 轨迹"解释。但空指令和乱码是分布外输入，这一条不能单独说明模型使用了指令中的信息（见"不能推出"）。
2. **只看布局能走到"抓起"，走不到"完成"。**
   - `empty` 下，策略仍然抓起正确的碗：稳定抓取从 5k 的 3 次增长到 20k/25k 的 41/35 次，约为有指令时的四分之一；抓起后几乎都能抬起。
   - 有接触的回合里，首次接触时刻与有指令时接近（25k：69 步对 68 步），说明这是同一个接近动作。
   - 但这些回合没有一次成功，掉落比例也更高（25k：14/35，有指令时 4/149）。
   - **解读：** 接近和抓取里存在一部分由布局驱动的运动程序，并且它随训练增强；完成任务需要语言。
3. **错误的指令会主动把策略引开，从 5k 就是如此。** `other` 下碰到原目标碗的次数是 2–19，远低于 `empty` 的 43–69。所以错误指令不只是"没有信息"，而是在把策略引向别处。
4. **`empty` 与 `gibberish` 的差别：** 乱码下首次接触明显更晚（25k：107 步对 69 步），掉落也更多。分布外的文本会额外干扰动作，不等同于"没有指令"。

## 不能推出

- **"成功依赖指令中的信息"。** 空指令下抓起后掉落 14/35（正确指令 4/149），更像分布外导致的动作质量下降，而不是"不知道放哪"。需要改写指令（同样信息、不同措辞）的对照来区分。
- **语言与布局在训练中完全混淆。** Spatial 的每个布局只配一条指令。`empty`、`gibberish` 是分布外输入，成功率归零也可能只是分布外崩溃，不能单独证明"使用了语言"。
- **`other` 条件还没有区分两种解释：**
  - 策略去抓当前场景里被指代的那只碗（语言 grounding）；
  - 策略复现那条指令在其原场景里的绝对轨迹（"语言 → 记忆轨迹"）。
  - 事件记录器只追踪原目标碗，分不出这两者。这由带轨迹记录的追加实验检验（`--trace`，结果待补）。
- 只有一个训练 seed。

## 轨迹追加实验：预注册判据（2026-10-11，结果出来之前写定）

**问题：** 另一任务的指令把策略引向哪里？
- **"钥匙"：** 语言调出一段绑定在绝对坐标上的运动程序，策略去往该指令在其原场景中目标碗的位置。这与 Action Atlas 的跨任务注入结果一致。
- **"语义定位"：** 策略去往当前场景中满足该描述的碗。

**数据：** `instruction_swap_eval.py --trace`，`other` 条件，5k/15k/25k 各 160 个回合；另跑 25k `correct` 作为校准。分析脚本为 `scripts/instruction_trace_analysis.py`。

**量的定义：**
- **到达点：** 第一次发出合夹爪命令后一步的末端位置；从不合夹爪时，取末端最低点。
- **记忆位置：** 源任务 j 的场景中、同一初态 ID 下目标碗（`akita_black_bowl_1`）的初始位置。
- 距离都取水平面（xy）距离。阈值 5 cm，约为碗的半径。
- **DTW：** 末端轨迹与源任务 j 的演示末端轨迹之间的 DTW 距离，对比与当前任务 k 的演示之间的 DTW 距离。演示取自原始 LIBERO HDF5。

**按场景分类（依据各场景的物体坐标）：**

| 场景 ← 指令 | 当前场景中符合描述的碗 | 用途 |
|---|---|---|
| task0 ← "next to the ramekin" | 两只碗离 ramekin 都约 13 cm，指代不明 | **排除**：记忆位置与当前 bowl_2 只差约 1 cm，两种解释预测相同 |
| task1 ← "from table center" | 不明确 | 辅助：记忆位置在空桌面 |
| task2 ← "on the cookie box" | **不存在** | **判决**：记忆位置正好是当前场景中没有碗的 cookie box |
| task3 ← "between the plate and the ramekin" | **不存在** | **判决**：记忆位置在空桌面 |

**每个回合的归类（只看 task1–3）：**
- **钥匙：** 到达点距记忆位置 ≤ 5 cm，且距当前场景所有碗都 > 5 cm。
- **去了一只真实的碗：** 到达点距当前场景某只碗 ≤ 5 cm，或抬起了某只碗。
- **其他：** 两者都不是，记为分布外失灵。

**判据（逐 checkpoint）：**
- task2+3 中"钥匙"占比 ≥ 50%，且源任务 DTW 中位数小于当前任务 DTW 中位数 → 支持"钥匙"。
- task2+3 中"去了一只真实的碗"占比 ≥ 50% → 反对"钥匙"。但在没有符合描述的碗的场景里，这不能证明"语义定位"，只能说明不是在复现记忆轨迹。
- **校准前提：** 25k `correct` 的成功回合中，到达点距目标碗 ≤ 5 cm 的比例应 ≥ 90%；不满足就说明到达点的定义不可用，先修正定义再下结论。

**本设计做不到的：** 正面证明"语义定位"需要当前场景中确实存在唯一满足描述的另一只碗，而 Spatial 0–3 的组合里没有这样的情况。需要另选任务组合或自建场景。

## 轨迹追加实验：结果（2026-10-11）

- **数据：** `other` 条件 5k/15k/25k 各 160 个回合，25k `correct` 160 个回合作为校准，16 个任务全部完成。
- **分析：** [trace_analysis_5cm.json](trace_analysis_5cm.json)（预注册阈值）、[trace_analysis_calibrated.json](trace_analysis_calibrated.json)（校准阈值）。

### 校准没有通过预注册阈值，阈值按校准数据修正

- 在 25k `correct` 的成功回合中，到达点距目标碗 ≤ 5 cm 的只有 102/136 = 75%，低于预注册的 90%。
- **原因：** 夹爪合在碗沿上。task 0 的中位数是 6.4 cm，碗的半径比预设的 5 cm 大。
- **修正：** 按预注册"先修正定义再下结论"的规定，阈值改为校准数据（只用 `correct` 回合）的第 90 百分位，即 **6.6 cm**（123/136 通过）。
- **透明度说明：** 修正时 `other` 的结果已经出来，所以下面两个阈值的结果都列出。DTW 判据和"去了真实的碗"的比例不依赖阈值。

### 判决（只看 task2、task3 场景，各 checkpoint 80 个回合）

| | 钥匙比例（5 cm） | 钥匙比例（6.6 cm） | 去了真实的碗 | DTW 中位数：源任务演示 / 当前任务演示 |
|---|---:|---:|---:|---:|
| 5k | 0.31 | 0.49 | 0.00 | 0.8 / 2.7 cm |
| 15k | 0.45 | **0.61** | 0.00 | 0.8 / 2.6 cm |
| 25k | 0.39 | **0.59** | 0.00 | 0.8 / 2.4 cm |

逐场景（6.6 cm；钥匙 / 去了真实的碗 / 其他，每格 40 个回合）：

| 场景 ← 指令 | 5k | 15k | 25k | 说明 |
|---|---|---|---|---|
| task0 ← prompt1（排除） | 5 / 23 / 12 | 1 / 36 / 3 | 2 / 38 / 0 | 记忆位置就是当前的 bowl_2；25k 抓起 bowl_2 29 次 |
| task1 ← prompt2 | 5 / 0 / 35 | 24 / 0 / 16 | 32 / 0 / 8 | 记忆位置在空桌面 |
| task2 ← prompt3 | 34 / 0 / 6 | 40 / 0 / 0 | 40 / 0 / 0 | 记忆位置是当前场景里没有碗的 cookie box |
| task3 ← prompt0 | 5 / 0 / 35 | 9 / 0 / 31 | 7 / 0 / 33 | 到达点距记忆位置中位数约 8 cm；15k/25k 有 5–7 次抓起 ramekin |

**DTW：** 在所有 480 个 `other` 回合中（3 个 checkpoint × 4 个场景，没有一个例外），接近段的末端路径都更接近**指令所属任务**的演示，而不是当前场景所属任务的演示。task1–3 场景中，前者的中位数为 0.6–1.1 cm，后者为 2.1–9.5 cm。

### 结论

1. **另一任务的指令调出的是那个任务的演示轨迹，即"钥匙"。**
   - 按校准阈值，15k、25k 满足预注册的"支持钥匙"判据（钥匙比例 ≥ 50%，且源任务 DTW 更小）；5k 为 0.49，差一点。
   - 按预注册的 5 cm 阈值，校准本身不通过，按规定不据此下结论。
   - 不依赖阈值的两项都指向同一方向：
     - 480/480 个回合的路径更接近源任务的演示；
     - 在 task2/3 场景中，没有一个回合去了当前场景的真实的碗。
2. **在当前场景里不存在被描述的碗时，策略不会去找"最像"的碗，而是走到那条指令在原场景中的绝对位置。**
   - 最清楚的是 task2 ← "on the cookie box"：15k、25k 全部 40/40 个回合走到记忆位置，也就是当前场景里空着的 cookie box。
3. **5k 已经如此。** 指令 → 轨迹的绑定在能力形成之前就有了，与 F13 中"5k 就会被引开"一致。
4. **与文献的关系。**
   - 这和 Action Atlas 的跨任务注入结果、LIBERO-PRO 的"走向记忆位置"一致。
   - 区别在于：在这个 SmolVLA 谱系里，调出记忆轨迹的线索是**语言**，而不是画面。在 Spatial 中，画面本身足以识别任务（每个布局唯一），策略却按指令选程序。

### 不能推出

- **语义定位没有被检验。** Spatial 0–3 中没有"当前场景里恰好存在唯一满足另一条指令描述的碗"的组合。
- **阈值修正发生在看到 `other` 结果之后。** 6.6 cm 只由 `correct` 回合决定；结论 1 的阈值无关部分（DTW、真实的碗比例 0）不受影响。
- **task3 场景的到达点偏离记忆位置约 8 cm。** 原因未查（可能与场景中较高的 cookie box 上的碗有关），但 DTW 仍然指向源任务。
- 只有一个训练 seed。
