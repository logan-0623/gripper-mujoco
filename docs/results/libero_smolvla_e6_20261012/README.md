# E6：抓取窗口内，10k→25k 的差距由哪些 flow 步、哪一侧承担？

- **运行：** 2026-10-12，代码 `b059b67`，见 [run.sh](run.sh)、[jobs.log](jobs.log)（45 个任务全部退出码 0）。
- **脚本：** [flow_stage_mix.py](../../../scripts/flow_stage_mix.py)；汇总 [e6_analysis.py](../../../scripts/e6_analysis.py) → [e6_summary.json](e6_summary.json)。
- **原始数据：** 服务器 `acquisition/e6_20261012/`。
- **判据：** 在运行前预注册，见 [研究问题](../../research-questions.md) 的 E6 一节。

## 设计

- **基本框架（同 E2）：** 10k 与 25k 同步运行；窗口外始终由 10k 执行。窗口从夹爪距目标 ≤ 10 cm 开始，到稳定抓起并抬高 2 cm 结束。
- **窗口内：** 10k 的动作块由混合速度场积分得到。
  - flow 共 10 步，k = 0 为纯噪声端。
  - 每一步用哪个模型的 expert、读哪个模型的前缀缓存（VLM 侧，含状态投影），由组别决定。
  - 两个模型共用同一观测和同一初始噪声。
- **等价性检查：** 全 10k、全 25k 两组的输出与原模型逐元素一致；窗口外的路径与原模型差为 0。
- **混合的生效时机：** 从窗口打开后计算的第一个动作块开始，最多比窗口打开晚 9 步。各组时机相同。

| 组 | 窗口内 |
|---|---|
| N | 全 10k |
| A | 全 25k |
| E | flow 第 0–4 步用 25k，第 5–9 步用 10k |
| L | flow 第 0–4 步用 10k，第 5–9 步用 25k |
| V | 25k 的 VLM 侧 + 10k 的 expert |
| X | 10k 的 VLM 侧 + 25k 的 expert |

- **评测：** Spatial 0–3。
  - 不推：初态 0–39，每组 160 个回合。
  - 推 8 步：N/A/E/L，初态 0–19，每组 80 个回合，推法同 E3b。
  - 另外补跑了 E3b 的 task 2–3。

## 结果

**不推（/160）**，补回比例 = (组 − N) / (A − N)，均为配对 bootstrap 95% CI：

| 组 | 成功 | task 0/1/2/3 | − N | 补回比例 |
|---|---:|---|---:|---:|
| N | 88 | 27/6/31/24 | — | — |
| A | 123 | 34/22/34/33 | +0.22 [+0.15, +0.29] | — |
| **E**（前半 25k） | **119** | 35/19/38/27 | +0.19 [+0.13, +0.26] | **0.89 [0.63, 1.19]** |
| L（后半 25k） | 104 | 32/8/32/32 | +0.10 [+0.04, +0.16] | 0.46 [0.23, 0.71] |
| V（25k VLM） | 103 | 27/9/35/32 | +0.09 [+0.04, +0.15] | 0.43 [0.19, 0.71] |
| **X**（25k expert） | **120** | 32/26/35/27 | +0.20 [+0.12, +0.28] | **0.91 [0.61, 1.28]** |

- **E − L：** +0.09 [+0.03, +0.16]。
- **V − X：** −0.11 [−0.19, −0.03]。

**预注册判决：**
- 前提成立：A − N 的 CI 下界大于 0。
- **"早期步承担"成立：** E − L 的 CI 下界大于 0，且 E 的补回比例为 0.89，不低于 2/3。

**推 8 步（/80）：**

| 组 | 成功 | 保持率 | − N |
|---|---:|---:|---:|
| N | 18 | 11/47 = 0.23 | — |
| A | 29 | 20/61 = 0.33 | +0.14 [+0.03, +0.25] |
| E | 27 | 15/59 = 0.25 | +0.11 [0.00, +0.23] |
| L | 21 | 13/54 = 0.24 | +0.04 [−0.04, +0.11] |

推 8 步后，E − L = +0.08 [−0.03, +0.19]。

**E3b 补齐到 task 0–3**（10k、25k 单独评测，初态 0–19）：
- 推 8 步后成功：10k 18/80，25k 35/80。
- 保持率：10k 15/50 = 0.30，25k 30/69 = 0.43。
- 只看两者不推都能成功的 43 个初态：25k − 10k = +0.21 [0.00, +0.42]。

## 结论

1. **F7 的离线量在闭环中有对应的因果作用。**
   - 窗口内只把 flow 前半段换成 25k，就补回了窗口内差距的约 90%；只换后半段只补回约 46%，两者之差显著。
   - F7 测到的变化（训练后，观测在 flow 第 3–4 步对动作计划的纠正力更强）也落在前半段。
   - 这是本项目第一次把一个内部量和闭环成功率因果地连起来。
2. **窗口内，主要承担差距的是 expert 侧。**
   - 25k 的 expert 读 10k 的 VLM 缓存，补回约 91%；反过来只补回约 43%。
   - 这与 F10 并不矛盾。F10 是 5k↔25k、整条 episode 的移植，两侧都需要；这里是 10k→25k、只在窗口内替换，此时 10k 的 VLM 侧已经够用。
3. **前半段补回的主要是"不推时能否抓成"，吸引域宽度没有可测的增加。**
   - E 推 8 步后的保持率是 0.25，与 N 的 0.23 接近；A 是 0.33。
   - 推偏的样本少，E − L 和保持率的差都不显著。

## 不能推出

- **flow 步只切成两半。** F7 的变化集中在第 3–4 步，"恰好是第 3–4 步"还需要更细的切分（例如 0–2 / 3–4 / 5–9）来检验。
- **补回比例不可加。** E + L = 1.35，V + X = 1.34，各部分之间有交互，所以不能说"前半段占 89%"。
- **只有一个训练 seed，只比较了 10k 与 25k。** 混合最多晚 9 步生效。
- **V/X 只做描述。** 预注册中没有为它们设定判据。
