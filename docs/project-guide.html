01 / THE QUESTION

你究竟在研究什么？

想象机器人执行“抓起物体，放进容器”。摄像头看到了接触，夹爪最终也完成了动作，但成功率本身不能告诉我们：模型内部有没有表示“已经接触”“抓得稳不稳”，以及动作是否依赖这些信息。

你的项目把这个问题拆成三个可以分别测量的层次。核心对象是策略内部的隐藏表示，主要实验平台是 LIBERO，策略是 SmolVLA；你用模拟器状态提供物理标签，再分析网络激活。

Read out

能读出什么？

给一个小分类器隐藏向量，它能否判断当前接触或稳定抓取？这叫 accessibility。

Intervene

哪些方向影响动作？

改变隐藏表示中的特定方向，观察动作变化，并与匹配随机扰动比较。这是功能作用的证据。

Act in a loop

是否影响交互结果？

让机器人真正执行后续动作，观察抓取保持、掉落和任务成功。这是闭环行为层面的验证。

我研究机器人策略内部的物理交互表示：这些信息在微调中怎样变得可读出，以及它们与动作生成和闭环行为有什么关系。

项目依据：README 开篇与测量框架；研究问题与证据登记。

为什么“读得出”与“用得上”是两回事？

隐藏向量可能同时包含背景、任务进度和动作计划。外部 probe 能利用其中的信息，不代表原策略的后续网络也使用同一个方向。类似于你可以从一段录像猜出时间，却不能因此认定机器人是按时间做决策。

干预比读出更进一步，但改变一个向量让动作变了，也可能是一般性破坏。必须看变化是否具有方向或因素特异性，并最终观察环境中的后果。

02 / THE RESEARCH JOURNEY

每一次转向，都来自前一个实验的问题

先尝试把交互结构直接交给策略

早期以 MuJoCo / Franka 操作为平台，把物体、夹爪及其关系组织成 Interaction Graph，再与 Flat 输入的 ACT 比较。这里的问题是：结构化输入是否有助于控制？

发现 Graph 预测质量和控制表现没有同步

预测 Graph 条件的平均成功率较高；ReflectVLM 预训练让估计更接近 teacher，却没有稳定地进一步提高控制成功率。这促使你区分“标签更正确”和“策略更容易利用”。

把 Graph 从输入模块改成测量语言

主线迁移到 LIBERO + SmolVLA。物理标签用于评估网络内部，而不要求把 Graph 输入主策略。你开始比较训练阶段、网络位置和交互因素。

先看到可读出性，再检验功能作用

Contact、StableGrasp、Phase 在早期 SFT 后更容易从动作路径读出，但 StableGrasp 的线性方向干预没有超过匹配随机对照。官方模型对照也得到相似负结果。

允许特征按模型自己的结构出现

你用无标签的 SAE 分解激活，先按稳定性与覆盖选特征，再观察语义和动作效应。目前得到四个离线正效应候选，正处于复现阶段。

之前的 Recovery RL 工作放在哪里？

项目探索过扰动后的恢复控制，也实现了部分 PPO / SAC 实验管线。但 recovery 分布校准没有把冻结 SFT 的成功率落在预设的 30%–50% 区间，正式 RL 扩展因此暂停。它说明你做过恢复任务的工程和校准，尚不能支撑“RL 重组了交互表示”的结论。与导师介绍时，作为研究范围的背景即可。

03 / HOW IT WORKS

先理解系统，再记技术名字

整个项目有两条并行路径：策略路径从图像、语言和机器人状态生成动作；测量路径从模拟器状态构造标签，并把这些标签与网络激活对齐。

CONTEXT视觉语言上下文编码图像和文本，形成动作计算可读取的上下文
ACTION EXPERT多次去噪更新结合上下文，把带噪动作逐步变成连续动作块
CONTROL动作与环境反馈执行动作，得到新观测；离线分析只运行到动作输出
测量路径

模拟器真实状态 → Contact / StableGrasp 等标签；同一观测 → checkpoint 前向计算 → 保存固定 tap 的激活；最后用 probe 和 intervention 比较两者。

技术背景：SmolVLA、LIBERO、ACT；本项目具体配置见 主配置。

Flow matching、action chunk、denoising 分别是什么？

Action chunk 是未来一段动作的集合。这里网络生成 50 个动作位置，不意味着一次开环执行全部 50 步；生成长度和实际执行调度是两个参数。

Flow matching 学习如何把噪声分布中的动作样本连续地推向示范动作分布。推理时从噪声出发，重复计算更新方向，逐步得到动作。项目沿用 denoising 一词描述这些更新步骤。

每个环境时刻，可以包含多次内部去噪计算。因此要区分三种“时间”：模型训练进度、单次推理的去噪步骤、机器人在环境中的执行时间。

你的工程工作是把示范数据、相机观测、模拟器重放和标签对齐，再让所有 checkpoints 使用同一组 state IDs。这样观察到的差异更容易归因于模型变化，而不是两次抽到了不同场景。

为什么不能把 13,603 帧随机分成训练集和测试集？

同一 episode 的相邻帧非常相似。如果前一帧在训练集、后一帧在测试集，模型可能通过记住场景获得虚高分数。项目让所有帧跟随所属 episode 分组，并另外提供 task-group 划分。

Episode holdout 检验同类任务中换一条轨迹；task holdout 检验没见过的任务组。二者回答的问题不同。“跨多个任务出现”也不等于“对未见任务泛化”。State Bank episodes 被排除在本项目 SFT 训练之外；这一保证不能自动扩展到外部官方 checkpoint 的全部训练数据。

04 / THE MEASUREMENT

你是怎样观察网络内部的？

先固定“训练阶段 × 网络位置 × 物理因素”

训练阶段使用嵌套数据子集：D25 ⊂ D50 ⊂ D100。25%、50%、100% 指训练数据覆盖，@16k 等表示优化更新次数。三条 SFT run 都从同一个 base 独立开始，不是从 D25 继续训练成 D50。

Pretrained
D25：@16k
D50：@16k → @32k
D100：@16k → @33k → @50k → @66k

比较 D25@16k 与 D100@16k，主要观察数据覆盖；比较 D100@16k 与 D100@66k，主要观察继续优化。实际步数是近似匹配，例如 16,070、16,324、16,617，报告保留精确值。

Tap抓取的位置怎样理解
vision_output图像 embedding 输出视觉 token 表示；每个视角有效 token 汇总后拼接。
multimodal_fusion第一次 prefix / prefill hidden state图像、指令和机器人状态形成的上下文。
action_expert_input最后一次去噪的 action_time_mlp_out当前带噪动作和时间步的 embedding；原始形状 50 × 720，沿动作位置均值汇总。
pre_action最后一次 action_out_proj 的输入靠近连续动作输出的 expert 表示。

Probe：冻结策略，再训练一个“小读出器”

先固定 checkpoint，把观测送入策略并保存隐藏向量 h。再单独训练一个简单模型，用 h 预测物理标签 y；二分类可以理解为 p(y=1|h) = sigmoid(wᵀh+b)。训练 probe 不会让原策略变得更会抓取，它只是测量工具。

项目用 cross-fitting：每次只从训练 folds 学读出器，再预测未参与拟合的那一组。它还与 majority、task ID、instruction、normalized time 等 shortcut 基线比较。原始分数高不够，必须超出“只看任务或进度也能猜到”的水平。

AUPRC、Macro-F1、utility 和置信区间怎么读？
  • AUPRC：precision–recall 曲线下面积，常用于接触／抓取等二分类；受正样本比例影响，必须放在相同评估分布中比较。
  • Macro-F1：分别算每一类的 F1 再平均，避免只在数量最多的阶段表现好。
  • Geometry 的误差：以 normalized MAE 等度量，通常越低越好；不能与分类指标直接比数值。
  • Probe utility：相对最强 shortcut 的优势，并统一“越大越好”的方向。零是基线水平，不是零信息。
  • Cluster bootstrap：以 episode 或 task 为重采样单位估计区间，避免把相邻帧当成独立样本；它没有覆盖重新训练 VLA 的全部随机性。

Intervention：在内部动一下，再看动作怎么变

线性 probe 的方向被用来构造因素相关扰动。在同一状态、同一策略噪声下，分别计算原动作、目标方向干预动作、匹配随机方向干预动作。

U = ‖a_target − a_original‖₂ − ‖a_random − a_original‖₂

U > 0 表示目标方向比该随机对照更影响动作。项目主要看动作块的第一个动作，并拆分 translation、rotation、gripper；“第一动作”是离线计算出的待执行动作，不是已经观测到的机械臂运动。

“匹配随机”匹配了什么？为什么仍然有限？

随机对照用于控制扰动本身的大小和位置；当前实现使用同 rank、同 norm、与目标方向正交的随机方向，并施加在相同调用和 token 位置。

同范数不等于相同的数据分布或下游敏感度。720 维空间中的随机方向可能与模型日常使用的动作子空间很不同。因此超过一个随机方向提供的是特定协议下的动作效应证据。

此外，当前 hook 只在最后一次去噪调用，将同一个均值向量变化加到全部 50 个动作位置。这一选择定义了负结果的适用范围。

SAE：从模型激活中寻找稀疏“组成成分”

一个 720 维向量可能同时混合很多因素。稀疏自编码器把它映射成更宽的特征字典，每个样本只激活少量特征，再重建原向量。这里字典宽度为 1,440，每个样本保留 32 个活跃特征，训练 5,000 次更新。

隐藏向量 h → 稀疏系数 z → 重建 ĥ
移除特征 j：h′ = h − zⱼ · dⱼ

dⱼ 是该特征的 decoder 方向。上式是直观形式；实现把标准化尺度换回原激活空间后施加变化，并保留原始激活的其余部分。SAE 特征编号只是某个字典里的索引，不是模型自带的“第 981 个抓取神经元”。

你先训练三个 SAE，再按 decoder 方向一致性、激活相关性、task / episode 覆盖和分布熵，冻结八个候选。之后才检查 Contact / StableGrasp / Phase 关联与动作效应。这就是 label-blind selection：选择过程不根据想要的语义答案挑特征。

为什么报告 SAE seeds、dead features 和 BH correction？

SAE seed 检查字典是否依赖某次随机初始化；它与 VLA 训练 seed、环境 seed、策略采样噪声都不同。

Dead feature 指在所检查样本上没有激活的字典项。大量 inactive atoms 表明需要谨慎看待字典利用率；高重建分数也不保证发现了独立、有物理含义的概念。

BH correction 用于控制一组检验中的错误发现率。这里针对八个冻结候选进行校正。它不会修复测试样本泄漏，也不会自动把离线结果转成闭环因果结论。

实现入口：taps · cross-fit probes · intervention · SAE discovery。

③ 可读出的 StableGrasp 方向，没有更强的离线动作效应 门限未通过

在 1,600 个配对状态上，四个纵向 checkpoints 都没有出现目标方向超过匹配随机对照的正功能招募结果。这表明可读出性提升与该干预下的动作作用并不同步。

为什么 paired ΔU 为正，也可能仍然没有通过功能门限？

U 是一个 checkpoint 内的“目标效应减随机效应”；ΔU 是两个 checkpoint 之间 U 的变化。比如 U 从 −0.2 变成 −0.1，ΔU 是 +0.1，但目标方向仍然弱于随机方向。

高重建质量与大量 inactive atoms 怎么同时发生？

三个 SAE 的 held-out explained variance 为 0.9974–0.9979，但 validation 上每个字典只有 187–217 个 atoms 活跃。少量有效特征仍可能很好地重建当前数据，剩余容量没有被利用。仅凭 dead-feature 比例不能确定原因，可能涉及数据的有效维度、稀疏预算或训练设置。

06 / THE RESEARCH CONTEXT

最近的论文发现了什么？

相关工作正在从“隐藏向量能预测什么”，走向“内部变化怎样影响行为”。下面四篇直接对应 VLA 项目，两篇帮助理解 Qu 教授的研究视角。它们是不同方法和设置下的证据，不能合并成一个无条件的“学界定论”。

Not All Features Are Created Equal

Grant、Zhao、Wang · 2026-03 · 机制研究；arXiv 页面注明 ICLR Multimodal Intelligence Workshop 接收

在六种模型上组合激活注入、SAE 和 probe。报告了视觉路径对动作的强影响，以及多路径架构中目标语义和运动计算的分工。逐 token 处理与均值 pooling 的行为保真度可能相差很大，结果也依赖架构。

与你的关系：直接覆盖 SmolVLA 和动作路径分析。它支持检查 token / 干预位置的必要性；其整层重建实验与本项目的 pooled 增量干预并不相同，不能直接断言你的 hook 已被该论文证伪。

Sparse Autoencoders Reveal Interpretable and Steerable Features in VLA Models

Swann 等 · 2026-06 更新版 · 稀疏特征与行为干预；预印本

研究哪些 SAE 特征跨 episodes 出现，哪些更像特定 episode 的模式，并通过 LIBERO 和 DROID 硬件上的 steering 检查行为变化。部分运动或语义特征的增强会产生与解释一致的行为。

与你的关系：跨任务／episode 的可解释特征已是明确研究线。你的贡献需要落在物理标签、训练轨迹或语义与动作作用的关系上。

Event-Grounded Sparse Autoencoders for Vision-Language-Action Policies

Jin 等 · 2026-05 · 事件关联的解释方法；预印本

用机器人轨迹中的关键帧和事件关联 SAE 特征，再做闭环干预。报告显示，离线重建质量不能单独预测闭环保真度；动作专家中的强干预还可能造成广泛行为崩溃，难以区分精细语义作用。

与你的关系：该工作把行为事件作为外部参照，你用模拟器定义的物理因素。两者可以互补；关键在于标签或事件是否帮助解释具体行为，而不只是命名特征。

VLA-Trace

Shi 等 · 2026-08-30 更新版 · 表示与行为诊断框架；预印本

在 π0.5 和 OpenVLA 上，通过 checkpoint-drift CKA、attention knockout 和 rollout 行为测试，研究微调重组了什么、动作依赖哪些模态，以及语义指令是否真正被遵循。两种架构呈现不同的适应与路由模式。

与你的关系：你的纵向研究应突出“固定状态上的具体物理因素”，而不只展示表示整体发生变化。CKA 衡量整体相似度，不能告诉我们究竟是 Contact 还是其他信息变化了。

Towards Effective Theory of LLMs: A Representation Learning Approach

Ustaomeroglu、Guannan Qu · 2026-05 · RET 表示学习框架；预印本

RET 从 LLM hidden-state trajectories 学习较紧凑的宏观状态，采用 BYOL / JEPA 风格的自监督预测目标。关注抽象、近似封闭的状态演化和实际解释用途；在所测 LLM 设置中报告了时间一致性、行为预测和生成干预结果。

与你的关系：SAE 问“激活可以拆成哪些稀疏成分”，RET 更关注“什么状态足以描述计算怎样演化”。后者为你的时间与控制问题提供了一个可讨论的视角，机器人版本仍需要单独定义。

Internal Planning in Language Models: Characterizing Horizon and Branch Awareness

Ustaomeroglu 等，含 Guannan Qu · 2026-02 更新版 · 内部规划诊断；ICLR 2026 接收

用 VQ-VAE 把高维隐藏状态压缩成离散 summary codes，再研究规划跨度和备选分支信息。论文报告的有效规划跨度依赖任务，模型也保留了部分未采用但有效的后续路径信息。

与你的关系：它把“网络包含未来相关信息”变成可测问题。你当前的 NextRelation 标签尚有类别支持限制，不能把它直接说成已证实的机器人内部规划。

从这些论文中，哪些认识可以稳妥带走？

证据支持的认识仍然开放的问题
VLA 激活中能够找到运动、任务或语义相关结构。来源这些结构是否构成独立、稳定、跨分布的物理概念？
部分激活干预会产生可观测的行为变化。来源变化来自特定机制，还是一般性破坏／动作输出偏移？
表示重建与行为保真度需要分别评估。来源什么压缩或特征选择原则能够可靠保留控制所需信息？
不同架构的微调变化和模态依赖并不一致。来源哪些机制能在架构、任务和训练阶段之间迁移？

这些证据尚未形成“SAE 特征等于物理概念”或“可解释表示必然提高成功率”的共识。你的研究正好处在这个尚未建立对应关系的地方。

07 / WHAT REMAINS UNRESOLVED

瓶颈：你已经测到现象，还没有唯一解释

目前最核心的瓶颈是：同一个离线结果，仍可能对应几种不同机制。下面把已知边界和下一步可能回答的问题放在一起。它们是理解研究现状的地图，不是一份必须立即执行的实验清单。

瓶颈为什么影响理解对应的方向
语义与动作编码混在一起主要 tap 直接来自带噪动作和时间；接触／阶段标签也与动作强相关。区分“计划中的动作”能解释的信息，与额外的物理交互信息。
干预方向和位置有限最后去噪步骤的 pooled 线性方向，不能覆盖全部 token、层或计算阶段。定位信息在哪个计算环节被读取或转成动作，而不是给单一负结果一个全局解释。
动作数值还未连接到闭环事件夹爪输出强度变化，不一定等于开合状态、接触力或任务结果变化。以抓取保持、释放时机和物体运动定义行为意义。
纵向结果与 SAE 结果来自不同模型链自训练 checkpoints 的读出变化，不能由官方 checkpoint 的 SAE 效应直接解释。在同一模型链上跟踪同一种功能判据。
泛化与独立复现范围有限当前包含 episode 相关性、训练随机性和部分标签类别支持的限制。明确结论属于哪些任务、训练 recipe 与重复实验。
README 里有哪些说法，交流时应该再精确一点？
  • “语义在动作路径出现”可以具体说成“在该 tap 的线性可读出性，早期 SFT 后超过了 shortcut”。
  • “没有 gross OOD shift”目前主要依据激活范数接近；范数接近不能独立证明仍在正常分布上。
  • “causal features”在当前记录中对应离线动作干预门限；清楚说成“有离线动作效应的候选”更容易解释。
  • “跨 seed 稳定”目前包括字典方向和激活匹配，其他字典上的独立动作干预仍是下一步。

物理因素与控制特征的对应

继续解释 Contact、StableGrasp、Phase 和模型内部动作特征之间的关系。重点是找出何时对应、何时分离，以及分离如何影响行为。

RET 的核心概念，用你自己的项目来理解

可以把“宏观状态”理解为一份压缩的计算摘要：忽略许多细节，但保留对当前过程和下一步有用的信息。对于你的机器人，一个候选摘要可能包含接近目标、形成接触、抓取保持等结构；它是否应当对应人工标签，是研究问题本身。

近似封闭问的是：知道这个摘要后，再提供原来的全部微观信息，能否显著改善对下一摘要的预测？如果仍然必须依赖大量被丢掉的信息，这个摘要就不足以描述动态。RET 在其确定性 LLM 设置下，使用匹配预测器的 held-out self-prediction 来评估这一性质。RET §3.1。

最重要的区别：机器人有外部环境和控制输入。

相同“正在接触”的内部状态，执行闭合夹爪或后撤会产生不同后果。讨论机器人宏观状态时，需要把动作、观测历史和环境状态的可观测程度放进问题定义。

候选研究形式：zt+1 ≈ T(zt, at, language)
z：紧凑内部状态　a：实际执行的动作

这是与你项目相关的建模设想，尚不是成立的结论。若单个 z 不足以描述接触和环境变化，可能需要历史信息或 belief state。状态太平滑也可能把接触瞬间抹掉，因此“动态一致”与“事件敏感”需要一起考虑。

不要混淆三种轨迹：SFT、去噪、机器人执行

训练轨迹：从 pretrained 到不同 SFT checkpoints，研究参数学习如何改变表示。

计算轨迹：同一观测下，action expert 的多次去噪调用，研究动作在网络内部如何形成。

环境轨迹：机器人执行、得到反馈，再次计算动作，研究真实交互如何演化。

RET 风格问题可以分别作用于计算轨迹或环境轨迹，但状态定义与转移条件不同。与你导师讨论时，先说清楚你指哪一种时间。

最值得向他请教的三个问题

  1. 我应该用什么标准定义“对控制有用的内部状态”？是能预测下一交互事件、保留动作相关信息，还是具有可验证的干预效果？这些标准怎样组合才不循环论证？
  2. action expert 输入处的结果，怎样区分动作编码和物理状态表征？目前可读出性与线性方向作用不一致，哪一种替代解释最值得先澄清？
  3. 把 RET 的状态观带到机器人时，应该先建模内部计算，还是策略与环境的联合动态？在部分可观测、接触不连续的环境中，“近似封闭”应如何定义？

这些问题从你已有结果出发，能让对话进入研究判断；不需要在第一次见面时承诺一个完整的新算法。

My project studies how vision-language-action policies represent physical interactions, such as contact and stable grasping. I separate three questions: what information can be decoded from the model, which internal directions influence its actions, and whether those directions matter for closed-loop behavior.

The main setup uses SmolVLA on LIBERO. The project has a shared, simulator-grounded state bank, so different checkpoints are evaluated on exactly the same observations and physical labels. With the upstream vision pathway frozen, contact, stable grasp, and phase become more linearly accessible early in fine-tuning. But interventions along the pooled stable-grasp probe direction do not change actions more than matched random directions.

A follow-up on an official checkpoint found the same limitation. Label-blind sparse feature discovery then produced preliminary candidates with larger offline action effects, mainly on gripper magnitude. Their closed-loop significance is still unresolved.

This led me to your work on representational effective theory. I would like to discuss how to distinguish an action encoding from a useful interaction state, and what a compact, dynamically meaningful representation should preserve in a robot interacting with an environment.

导师可能追问什么？

“你自己做了哪些工作？用了哪些现成组件？”

现成组件包括 MuJoCo、LIBERO、LeRobot、ACT 与 SmolVLA。项目新增的是交互标签与重放对齐、State Bank、纵向 checkpoint 协议、tap 提取、分组 probe、干预和 SAE 分析管线。你可以按自己实际负责的部分说明设计、实现、运行与分析的分工。

“你的主要发现是什么？”

在已测 expert-only SFT 条件下，一些交互标签更易从动作路径读出，但 pooled 线性方向没有更强的匹配对照动作效应；无标签 SAE 候选呈现初步正效应。当前发现的是测量层次之间的不一致，原因仍待区分。

“为什么 Graph 后来不再作为主策略输入？”

Graph 输入实验检验结构化输入是否有用。后来研究问题变成 VLA 自己学到了什么，因此把物理关系用于标注和测量，让主策略保持其原本的观测到动作路径。

“这些可读出的东西，会不会只是动作的编码？”

这是合理且尚未排除的解释。主要 tap 直接由去噪动作和时间构成，因此需要区分物理因素与动作计划的贡献。这里没有理由提前回答“肯定不是”；可以说明它是当前最值得澄清的机制问题。

“为什么高重建质量不能证明 SAE 好？”

重建误差看所有维度的平均数值接近程度。控制可能只对少数位置或方向特别敏感，微小误差也能改变动作；反过来，一个高度可重建的动作向量也未必包含独立物理概念。

“你已经提高了闭环成功率吗？”

早期 ACT 的输入条件比较有控制成功率结果。当前 SmolVLA 表示研究尚未完成特征干预的闭环效用验证；官方模型 9/10 是单任务 baseline screen，不是特征干预提高了成功率。

“你希望从我的指导中得到什么？”

可以具体回答：希望厘清内部状态、物理标签与动作编码之间的关系，并找到一个有控制含义的动态表示定义。你已有可重放数据和诊断工具，最需要的是决定这些工具应该验证哪个机制。
