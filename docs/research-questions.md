# 研究问题：VLA 在训练中到底学会了什么

更新：2026-10-05。依据 [findings.md](findings.md) 中已确立的事实。原先"VLA 何时学会依据动作结果调整"那份草案已经被本文件取代，旧稿保存在 git 标签 `pre-restructure`。

## 一个好问题要满足什么

1. **有两个都说得通的答案，并且它们对同一个实验给出相反预测。** 不满足这一点，任何结果都能被解释，也就得不到 yes 或 no。
2. **判决量是行为：** 闭环成功率，或者训练改动带来的效果。探针准确率、千分位级的 RMS 差只能当测量工具，不能当判决。
3. **两种答案都会改变别人的做法。** 例如决定训练预算花在哪个模块上、要采什么数据、选什么优化器。
4. **用现有资产就能先做第一刀：** 同谱系的五个 checkpoint、StateBank、flow trace、强制掉落的分叉框架。

过去两个月的实验，大多卡在第 1 和第 2 条上。问题都是"信息在不在、有没有被用"。结果总是"能读出，但编辑它的效果不比随机方向强"，这个结论两种解释都能接受。

## 故事线

> **一个直觉说法是：VLA 先"理解"任务，然后才"会做"。我们的数据说的是另一件事。在能力形成的 10k 步里，探针能读到的交互知识几乎没有变；变的是策略在自己产生的状态上能否保持在正确的轨迹附近。**

如果这个说法成立，会带来三个改变：
- 可解释性研究应该从"找概念特征"转向"测量策略的吸引域"。
- 训练应该更关注策略偏离之后的状态。
- "更好地利用 VLM"可能不是当前的瓶颈。

如果不成立，我们就能确切知道 VLM 表征的哪一部分在训练中真的改变了，以及这种改变对动作有多重要。

下面五个问题按顺序支撑这条故事线。Q1 和 Q2 不需要新训练，可以马上做。

---

## Q1. 能力形成发生在哪个模块：VLM、动作专家，还是两者之间的接口？

**两种世界**
- **A（读出 / 执行侧）：** 5k 到 25k 的收益主要在 action expert 和投影层里。VLM 在 5k 时已经够用。
- **B（表征侧）：** 收益主要来自 VLM 和视觉编码器的变化（这个谱系是全量微调，VLM 确实在更新）。
- **C（共适应）：** 两侧的变化离不开对方，任何拼接都会崩。

**判决实验：跨 checkpoint 的模块移植，不需要训练。** 同一谱系从同一初始化出发，参数名完全一致，可以直接拼成混合模型：

| 组合 | 视觉 + VLM | expert + 投影层 |
|---|---|---|
| H1 | 5k | 25k |
| H2 | 25k | 5k |
| 对照 | 5k / 25k 原模型 | — |

在已有的 40 个配对初态（Spatial 0–3）上测闭环成功率。之后可以细分到视觉编码器、VLM 文本层、state_proj，以及 expert 读取 VLM KV 的那一层。

**Yes/No 判据（需预注册）**
- H1 达到 25k 成功率的 80% 以上（看 CI 下界），且 H2 接近 5k → 支持 A。
- 反过来 → 支持 B。
- H1 和 H2 都低于 5k → 支持 C，能力存在于接口的协同变化里。

**重要在哪里**
- 如果结论是 A，那么"VLM 语义没被用好"至少不是这个阶段的瓶颈。
- 如果结论是 C，那么 Knowledge Insulation 这类"冻结 VLM、只训 expert"的做法，代价要重新评估。
- Muon 等优化方向也知道该优先作用在哪个模块。

**成本与风险**
- 成本：每个组合跑 40 条 rollout，和现有时间轴评测的成本相同。
- 风险：模型拼接（model stitching）在 LLM 中已有先例。新意在于把它沿 VLA 训练时间轴展开，并用闭环成功率作为判据。立项前需要检索 VLA 方向的近邻工作。

## Q2. 5k 的失败来自"动作本身不对"，还是"小误差在闭环中累积"？

**两种世界**
- **A（累积误差）：** 在演示轨迹上的状态里，5k 与 25k 的单步动作误差相差不大。差距在闭环中被放大：5k 一旦偏离，就回不来。
- **B（单步就错）：** 即使在演示状态上，5k 的动作也明显更差，尤其是夹爪时机。

**判决实验（第一步零新增算力）**
1. 用已有 flow trace（512 个 StateBank 状态，五个 checkpoint 共用同样的状态和噪声），计算每个 checkpoint 实际执行的前 10 步动作与演示动作的误差，按阶段拆开（接近、抓取、搬运）。
2. **教师纠正 rollout：** 让 5k 策略执行，每隔 k 步把仿真状态重置回演示轨迹。观察成功率随 k 的变化。如果 k 很小时 5k 接近 25k，误差累积就是主要原因。

**Yes/No 判据（需预注册）**
- 演示状态上的离线误差差距不到闭环差距的一半，且教师纠正能恢复大部分成功率 → A。
- 离线误差已经能解释成功率的排序 → B。

**重要在哪里**
- 这是 BC 理论（compounding error）在 VLA 训练动态上的直接检验。
- 如果是 A：离线 loss 和探针都看不到能力形成，评估训练进度必须用闭环指标或吸引域指标；DAgger 类数据和扰动增强应该能加速能力形成。
- 如果是 B：问题回到"单步动作质量"，Q1 的定位更关键。

## Q3. 能力可以用"吸引域宽度"来度量吗？吸引域宽度在训练中如何变化？

**定义：** 在固定的扰动族下（强制张开夹爪、把物体平移 δ、把末端位置偏移 δ），策略仍能完成任务的最大扰动幅度。

**两种世界**
- **A：** 吸引域宽度随训练单调变宽，并且比离线 loss、探针指标更能预测每个任务的成功率。这也能解释 F1 中非单调的逐任务曲线。
- **B：** 吸引域宽度与成功率无关，或者早期就饱和了。

**实验**
- 在已有的分叉框架（`scripts/feedback_branch_pilot.py`）上扩展扰动族和扰动幅度。
- 每个 checkpoint、每个任务各画一条"扰动幅度—成功率"曲线。
- 用 5k、10k、25k 和留出初态做预注册检验。

**Yes/No 判据：** 在留出的任务和 checkpoint 组合上，吸引域宽度对成功率的秩相关明显高于离线动作误差（比较两者相关系数之差的 CI）。

**重要在哪里**
- 这把"可解释性"从"找特征"转为"测量一个控制论意义上的量"。
- 如果成立，它就是一个能复用到其他 VLA 的能力诊断工具。
- F6 中 Spatial 0 和 Spatial 1 的反差是第一个数据点。

## Q4. 内部表示能否提前预测"策略即将离开吸引域"？

**这一步才需要可解释性。** 在 Q3 的扰动 rollout 中，记录扰动后的隐藏状态，问一个问题：能否在失败发生之前，从隐藏状态判断这次会不会恢复？

**两种世界**
- **A：** 存在一个可读的"偏离信号"，并且它在 VLM 侧和 expert 侧的位置可以定位。
- **B：** 隐藏状态只能反映当前的物理状态（F2 已经看到这一点），预测不了能否恢复。这时恢复与否取决于动作映射在未见状态上的泛化，和表征无关。

**判决：** 按 episode 划分训练集与测试集，比较两种预测器的 AUROC：
- 只用"本体状态 + 时间 + 物体位姿"的预测器（F2 告诉我们这个基线很强）。
- 在此基础上再加入隐藏状态的预测器。

增量的 CI 大于 0 → A；否则 → B。

**关于近邻工作：** 已有工作用 VLA 特征做失败检测（例如 SAFE 和 FailPatch，均需核对原文）。本问题的区别在于以吸引域为标签，并且与本体基线做条件比较。

## Q5. 针对吸引域边缘的训练，能否用更少的步数达到同样的能力？

**这一步把诊断变成性能收益。**

**比较对象（相同的步数、数据量和算力）**
1. 原配方继续训练。
2. 加入扰动后由脚本控制器恢复的示范（恢复数据）。
3. 只加入动作噪声增强（DART 风格）。

主指标是"达到 80% 成功率所需步数"和吸引域宽度，并在留出任务上检验。

**Yes/No 判据：** 第 2 组或第 3 组在达到同样成功率时节省 ≥30% 的步数（CI 下界），且正常任务的成功率不下降。

**Muon 的位置：** 在这个框架里，优化器问题可以改写成"在相同步数下，哪个优化器让吸引域变宽得更快"。这比"Muon 是否让 loss 降得更快"更有信息量。但它应该放在 Q5 之后，作为一个比较维度，而不是作为主问题。

## 不再作为主线的方向

| 方向 | 原因 |
|---|---|
| 用语义标签方向（Contact、StableGrasp）做编辑 | 已经三次不超过随机方向（F3），继续做只能得到同样的不确定结论 |
| 用探针证明"先可读出、后会用"的形成滞后 | F2 显示可读性从一开始就饱和，这个问题已经有答案 |
| 单独提出"加强视觉—语言对齐"的方法 | Knowledge Insulation、APT、Anchor-Align 已经覆盖；需要先由 Q1 证明 VLM 是瓶颈 |
| 长任务 | 等 Q3 的吸引域度量建立后，再作为外推检验 |

## 立即可做的顺序

1. **Q2 第一步：** 用已有 flow trace 计算演示状态上的离线动作误差。零新增算力，约半天。
2. **Q1：** 写一个参数移植脚本，跑 H1 和 H2 两组，各 40 条 rollout。
3. **拉回 5k 和 10k 的强制掉落结果：** 逐条看 Spatial 0 的视频，确认失败是否属于物理上不可恢复。这一步也为 Q3 做准备。

前两步的结果出来后，再决定故事线是否成立，以及是否值得投入 Q3–Q5。
